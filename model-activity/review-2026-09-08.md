## Important qualifications from the earlier code-only review

- The old git diff call was a base-to-worktree comparison, not literally a two-dot revision expression. The stale-feature-branch failure exists locally. CI's synthesized merge checkout has a different topology; the integration test covers both rather than changing blindly to a HEAD-only three-dot diff that drops local edits.
- Full-context Git diffs identify existing status for content-only edits. Supplied partial diffs with no old status need conservative review; they cannot establish that a record was merely proposed.
- Labels assert review; they cannot prove a named human reviewed. A workflow change can remove a job unless remote branch rules require protected review. This remains an explicit deployment boundary.
- A version identifies an intended artifact, not every file in an untagged working tree. Development suffixes and coherent publication instructions address ambiguity without moving tags.
